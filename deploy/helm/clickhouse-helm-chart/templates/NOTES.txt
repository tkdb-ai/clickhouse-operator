{{- if .Values.ingress.enabled }}
ClickHouse HTTP interface is exposed via Ingress:
   URL: http{{ if .Values.ingress.tls }}s{{ end }}://{{ .Values.ingress.host }}
   (HTTP query API on port 8123 — use this for JDBC/ODBC drivers set to HTTP mode)

1. Get the ClickHouse Admin Password:
   echo "Admin Password: $(kubectl get secret {{ include "clickhouse.fullname" . }}-admin -n {{ .Release.Namespace }} -o jsonpath='{.data.admin}' | base64 --decode)"

2. Check the status of your ClickHouse Installation:
   kubectl get chi {{ include "clickhouse.fullname" . }} -n {{ .Release.Namespace }}

3. Monitor the Pods:
   kubectl get pods -n {{ .Release.Namespace }} -l clickhouse.altinity.com/chi={{ include "clickhouse.fullname" . }}

4. View ClickHouse Logs:
   kubectl logs -n {{ .Release.Namespace }} chi-{{ include "clickhouse.fullname" . }}-main-0-0-0 -c clickhouse

5. Secret Name for Reference:
   {{ include "clickhouse.fullname" . }}-admin

{{- if eq .Values.coordination.mode "keeper" }}

6. ClickHouse Keeper is deployed as the coordination service.
   CHK resource: {{ include "clickhouse.fullname" . }}-keeper
   Replicas:     {{ .Values.coordination.keeper.replicasCount }}
   {{- if eq (int .Values.coordination.keeper.replicasCount) 1 }}

   WARNING: 1 Keeper replica has no fault tolerance. Set coordination.keeper.replicasCount=3 for production.
   {{- end }}

   Check Keeper status:
   kubectl get chk {{ include "clickhouse.fullname" . }}-keeper -n {{ .Release.Namespace }}

{{- if .Values.backup.enabled }}

Backup REST API (port 7171) is available on each ClickHouse pod.
{{- if .Values.garage.enabled }}
   S3 backend: Garage (http://{{ .Release.Name }}-garage:3900, bucket: {{ .Values.backup.s3.bucket }})
   Credentials: auto-read from the garage-backup secret.
{{- end }}
   Scheduled: {{ .Values.backup.schedule | default "0 2 * * *" }} (CronJob: {{ include "clickhouse.fullname" . }}-backup)

   Create and upload a backup:
   kubectl exec -n {{ .Release.Namespace }} <pod> -c clickhouse-backup -- clickhouse-backup create-and-upload

   List remote backups:
   kubectl exec -n {{ .Release.Namespace }} <pod> -c clickhouse-backup -- clickhouse-backup list remote

   Restore a backup:
   kubectl exec -n {{ .Release.Namespace }} <pod> -c clickhouse-backup -- clickhouse-backup restore <backup-name>
{{- end }}
{{- if .Values.garage.enabled }}

Garage S3 is enabled.
   Endpoint (in-cluster): http://{{ .Release.Name }}-garage:3900
   Admin API:             http://{{ .Release.Name }}-garage:3903
   Bucket:                 {{ .Values.garage.bucket }}
   Credentials secret:    garage-backup
   ClickHouse storage policy '{{ .Values.garage.storagePolicy }}' is configured via s3_disk.

   The garage-setup post-install hook configures the layout, creates the
   bucket, and imports the access key automatically.

   List bucket contents:
   kubectl run -n {{ .Release.Namespace }} garage-ls --rm -i --restart=Never --image=amazon/aws-cli \
     --env=AWS_ACCESS_KEY_ID=$(kubectl get secret -n {{ .Release.Namespace }} garage-backup -o jsonpath='{.data.access-key-id}' | base64 -d) \
     --env=AWS_SECRET_ACCESS_KEY=$(kubectl get secret -n {{ .Release.Namespace }} garage-backup -o jsonpath='{.data.secret-access-key}' | base64 -d) \
     --env=AWS_REGION=garage \
     -- --endpoint-url http://{{ .Release.Name }}-garage:3900 s3 ls s3://{{ .Values.garage.bucket }}/
{{- else }}

Garage is disabled. Set garage.enabled=true to deploy an in-cluster S3-compatible store for backups and tiered storage.
{{- end }}
